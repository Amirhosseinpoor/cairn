# ADR-0011: Async runtime scope

- **Decision:** D-11 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Architecture

## Context

The main thread owns the TUI event loop and renderer at a 60 fps cap, while Tokio runs async tasks,
a Rayon pool (≤ 8) runs CPU-bound jobs, and a dedicated 2-thread blocking pool runs keychain and
SQLite calls (§3.3). D-11 fixes which class of work goes to which pool: without that split, parsing,
indexing and diffing have no dedicated home and CPU-heavy work sits where it can stall the runtime
the render loop depends on.

The render loop's budgets are normative: P-06 ≥ 45 fps P5 while streaming, P-07 ≥ 30 fps P5 while a
tool streams 1 MB/s, P-05 input latency ≤ 30 ms, and REQ-TUI-007 caps rendering at 60 fps with
delta coalescing. CPU work must also respect the load-shedding order of §13 (render > 16 ms/frame
→ drop to 30 fps; index CPU > 60% of a core for > 5 s → yield), and indexing explicitly must run
on the Rayon pool and never block rendering (REQ-CTX-008, T-CTX-009).

## Decision

**Tokio is used for I/O tasks only; CPU-bound work (parsing, indexing, diffing) runs on a `rayon`
thread pool of `min(8, num_cpus)`.** Per the spec's rationale: this keeps the render loop at 60 fps
under load.

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| Everything on tokio blocking pool | Rejected: it does not keep the render loop at 60 fps under load (the stated rationale for the choice). |

## Consequences

- Positive: rendering stays within P-06/P-07 while indexing and diffing run — CPU work is isolated from the stream/render path (T-CTX-009: no frame > 16 ms while indexing).
- Positive: the §3.3 thread inventory is explicit (render thread, 4 Tokio workers, Rayon ≤ 8, 2 blocking), which supports REQ-PERF-002's idle thread ceiling (≤ `2 + num_cpus/2`, T-PERF-008).
- Risks / costs: work must be dispatched to the right pool by hand — CPU jobs placed on Tokio, or blocking calls placed on the async runtime, silently reintroduce the stall this decision prevents.
- Risks / costs: the load-shedding ladder (§13) is still required as a backstop when Rayon work outruns its budget.
