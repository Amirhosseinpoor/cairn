# ADR-0006: Parsing

- **Decision:** D-06 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Technology

## Context

The same parsing need appears in four places: syntax highlighting (§10.5), symbol extraction for
the repository map (§5.2 extraction queries), post-edit syntax validation with byte-exact rollback
(§6.3.6 — an `ERROR`/`MISSING` node intersecting the edited range blocks the write with
`E-EDIT-SYNTAX`, REQ-TOOL-014/015), and AST-based shell-command safety analysis (`tree-sitter-bash`,
§9.3). The spec wants one query API across all of them, a concrete MVP language set (7 grammars —
`cairn doctor` check #12), and a way for users to load additional grammars dynamically via
`libloading` (§6.7.4, REQ-TOOL-028).

## Decision

Use **`tree-sitter` 0.24 with grammars compiled in-tree via `tree-sitter-*` crates, feature-gated**
(§15.2 ships bash, python, rust, typescript, go, java, cpp). Per the spec's rationale: one query
API serves highlighting, symbol extraction and post-edit syntax validation (§6.3.6). MVP grammars
are bundled; more can be added with `cairn config set languages.<id>.grammar_path` (§6.7.4).

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| `syn` / `rustc_ast` | Single language only. |
| `uni-grammar` | Not chosen; the spec picks tree-sitter's one-query-API model (no separate rationale recorded in SPEC §2.1). |
| `regex` | Not chosen as the parser; regex cannot deliver AST-based validation or extraction (§9.3 uses regex only *after* the AST extracts leaf command words). |

## Consequences

- Positive: one grammar/query layer backs highlighting (§10.5), repo-map symbols (§5.2), edit validation (§6.3.6) and shell AST safety (§9.3).
- Positive: the MVP set is fixed and loadable, so `cairn doctor` check #12 has a concrete list of 7 grammars to verify (§12.3).
- Risks / costs: languages outside the MVP set degrade to file-level indexing until a grammar path is configured (§6.7.4: load failure → `W-PARSE-GRAMMAR`, tested by T-TOOL-017).
- Risks / costs: validation must finish within 500 ms for files ≤ 1 MiB or the write proceeds with `syntax_ok: null` and `W-EDIT-VALIDATE-TIMEOUT` (REQ-TOOL-015, T-EDIT-024).
