# ADR-0012: Diff engine

- **Decision:** D-12 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Technology

## Context

Diffs are a core surface of Cairn: Build-mode approvals show a unified diff before an edit is
applied (scenario S-1), the diff viewer renders inline below 100 columns and side-by-side above
(`ui.diff_layout`, `ui.diff_side_by_side_min_width = 100`, T-TUI-029), and the viewer supports
hunk navigation with per-hunk accept/reject — `accept` writes the hunk with `edit_file` semantics
and `rejected` restores the original, all permission-gated in build (§10.5). The engine must
produce both inline and side-by-side views from one computation and stay pure-Rust inside the
workspace (checkpoint diffs themselves come from libgit2 `diff_tree_to_tree`, §9.8 — a separate
path).

## Decision

Use the **`similar` crate (Myers + patience hybrid) with unified output** (frozen at 2.6, §15.2).
Per the spec's rationale: it is pure-Rust, produces both inline and side-by-side views, and
supports hunk-level accept/reject.

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| `diffy` | Not chosen; the spec selects `similar` for its dual inline/side-by-side output and hunk-level support (no separate rationale recorded in SPEC §2.1). |
| `git` subprocess | Not chosen; the spec's rationale for the choice is a pure-Rust engine (a subprocess would also add an exec surface, cf. D-07's stated concern with subprocess designs). |

## Consequences

- Positive: one engine serves the approval diff, the §10.5 diff viewer (both layouts) and per-hunk accept/reject without shelling out to git.
- Positive: unified output gives the exact format approvals and exports show, and the threshold behavior (inline < 100 cols, side-by-side ≥ 100) is snapshot-tested (T-TUI-029).
- Risks / costs: hunk accept rewrites working-tree bytes, so the engine's hunk coordinates must stay byte-exact against files that may change between review and accept (the viewer applies `edit_file` semantics, §10.5).
- Risks / costs: diff cost sits near the render loop — §13's load-shedding rules apply if rendering a large diff threatens the 16 ms frame budget.
