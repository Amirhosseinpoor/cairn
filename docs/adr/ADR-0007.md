# ADR-0007: Search

- **Decision:** D-07 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Technology

## Context

Search powers file discovery, the `grep`/`glob` tools and repository Q&A (UC-4), so it must work
on a machine with nothing installed (zero-config onboarding, persona P3) and must honor the ignore
precedence of §5.1 (`.gitignore` variants → `.cairnignore`, root → deepest, explicit `include`
beating ignore files — REQ-CTX-001, T-CTX-001/002). Because `grep` is a model-facing tool, any
subprocess-based design would add an exec/PTY surface; the spec treats shell-injection surface as a
first-class risk (§9.3). Performance is budgeted: P-13 (10,000 files, simple pattern) ≤ 300 ms and
P-14 (100,000 files) ≤ 2.5 s.

## Decision

Use the **embedded ripgrep libraries: `grep-searcher` + `grep-regex` + `ignore`**, walking with
`ignore::WalkBuilder` and its ignore-rule engine (§5.1). Per the spec's rationale: the same
semantics and ignore-rule engine as ripgrep without requiring an external binary, no
shell-injection surface, and a walk that honors all ignore files. If the embedded walk fails
(e.g. ELOOP), the tool returns `E-GREP-WALK` (together with `E-GREP-CAP`/`E-REGEX-*` in the
§6.2 error set).

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| Subprocess `rg` | Breaks on machines without `rg` installed and adds PTY/exec complexity. |
| `grep` crate alone | Not chosen; the spec pairs the search crates with `ignore` so walking shares ripgrep's ignore-rule engine (no separate rationale recorded beyond the choice's rationale). |

## Consequences

- Positive: no external binary dependency and no exec surface for a hot tool path; ignore precedence (§5.1) is inherited from the same engine ripgrep uses.
- Positive: perf budgets P-13/P-14 are measurable against a well-known implementation, and binary/NUL handling is defined (T-CTX-005: grep skips binaries and counts `binary_skipped`).
- Risks / costs: walk-level failures must still surface as stable codes — `E-GREP-WALK`/`E-GREP-CAP` are covered by T-TOOL-119/T-TOOL-120, so the fallback path cannot be dropped.
- Risks / costs: symlink escapes must be caught by path checks rather than by the walk itself (`E-FS-ESCAPE` in read/glob/grep/index, T-CTX-004).
