# ADR-0010: Config format

- **Decision:** D-10 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Technology

## Context

Cairn's configuration is a hand-edited file (`~/.config/cairn/config.toml`, §11.4.1) that must
carry comments, support strict validation, merge across eight precedence layers (§11.5), and
round-trip into a machine-readable schema. Validation is strict by default: unknown top-level or
known-section keys are rejected with `E-CFG-UNKNOWN` unless `--allow-unknown-keys`, enums are
strictly validated (`E-CFG-BADVALUE`), and `schema_version` must be 1 or migration runs
(`E-CFG-VERSION`) — §11.4.2. The same Rust structs emit the JSON Schema at build time
(`schemas/config.schema.json`, §11.4.3), annotated with `x-env-var`/`x-flag`/`x-config-key` for
every §11.1 flag (REQ-ARCH-011, T-CFG-001).

## Decision

Use **TOML via `toml` 0.8** (versions frozen at M0, §15.2). Per the spec's rationale: comments
matter for a hand-edited config, `serde` derives integrate with the schema pipeline, and strict
unknown-key rejection is the default (§11.4.2).

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| YAML | Ambiguous scalars, indentation traps. |
| JSON | No comments. |
| XDG config in shell | Not chosen as the config format for the layered loader (no separate rationale recorded in SPEC §2.1; §11.5 still locates the *layers* in XDG paths). |

## Consequences

- Positive: comments survive hand editing; `serde` derives feed both the loader and the JSON Schema generator (§11.4.3, D-16).
- Positive: strict unknown-key rejection catches typos at `cairn config validate` with `file:line` spans, all errors at once (REQ-CLI-003, T-CFG-002).
- Risks / costs: Cairn documents one deliberate divergence from plain TOML — `key += [...]` list append semantics (§11.5 merge table, T-CFG-011) — which a TOML-naive editor or tool must be taught.
- Risks / costs: strictness means a config written for a newer `schema_version` fails on an older binary with `E-CFG-VERSION` until migration runs (§11.4.2, §11.7).
