# ADR-0014: Licensing of Cairn itself

- **Decision:** D-14 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Licensing

## Context

Cairn's business model is source-available with a separately sold commercial license (§2.1 D-14
choice cell), while still attracting outside contributors who need patent safety. The repository
carries a root `LICENSE` file (§15.1), and the README must state the license (§15.6 documentation
deliverables). The dependency side of licensing is D-13/ADR-0013; this decision covers Cairn's own
code.

Two properties pull in different directions: an open, permissive license keeps the project
approachable and consistent with the permissive-only dependency allow-list of D-13, while
contributors need protection beyond copyright — the risk that made "proprietary-only" and "MIT"
both candidates for rejection in §2.1.

## Decision

Cairn itself is licensed **Apache-2.0** — source available, with a commercial license sold
separately. Per the spec's rationale: the patent grant in Apache-2.0 protects contributors.

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| MIT | The spec records only the Apache-2.0 rationale: its patent grant protects contributors — MIT does not provide that. |
| Proprietary-only | Rejected by the choice: Cairn is source-available (a proprietary-only model contradicts the selected "source available" positioning). |

## Consequences

- Positive: contributors receive an explicit patent grant (the stated rationale), which is the reason Apache-2.0 was chosen over MIT.
- Positive: Apache-2.0 is itself on the D-13 allow-list, so Cairn's own license is consistent with the dependency policy applied to it (ADR-0013).
- Risks / costs: this decision has no `REQ-`/`T-` test of its own in §14.2 — it is enforced socially by the `LICENSE` file at the repo root (§15.1) and by the license statement in `README.md` (§15.6).
