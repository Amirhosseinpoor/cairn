# ADR-0009: Index storage

- **Decision:** D-09 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Architecture

## Context

The repository map needs a symbol graph with indexed lookups, transactions for incremental updates
from the file watcher, and headroom at 100k-file scale (§5.3: debounced `notify` events, sha256
invalidation, storm fallback to poll mode). Budgets constrain the storage choice: cold build
1,000 files ≤ 1.5 s, 10,000 ≤ 8 s, 100,000 ≤ 60 s usable after 5 s; warm load of 10,000 files
≤ 400 ms (§5.3 budgets; P-09..P-12). Indexing must never block rendering (REQ-CTX-008, T-CTX-009),
and a cold index must stay partially usable in degraded mode (REQ-CTX-009).

Crucially, the index is *derived* data: it must be deletable at any time and rebuildable from the
workspace (§5.3 invalidation rules — full rebuild on config, ignore-file or `index.schema_version`
change).

## Decision

**SQLite (`rusqlite`, bundled SQLite 3.45, WAL) at `~/.cache/cairn/index/<hash>.sqlite3`**
(`%LOCALAPPDATA%\cairn\index\` on Windows), where the hash is `sha256(workspace_root + provider-
neutral salt)` (§5.3). Per the spec's rationale: the symbol graph needs indexed lookups,
transactions for incremental updates, and 100k-file scale; the store is cache-only and deletable at
any time.

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| JSONL | Not chosen; the stated requirements (indexed lookups, transactions, 100k-file scale) are what drove the choice (no separate rationale recorded in SPEC §2.1). |
| `sled` | Immature, opaque format. |
| In-memory only | Not chosen; the spec's warm-load budgets (P-12, §5.3 warm column) and the cache-location rule describe a store that persists across runs while remaining deletable (no separate rationale recorded). |

## Consequences

- Positive: WAL plus transactions give the watcher incremental, atomic updates (§5.3 create/modify/remove/rename mapping) with concurrent readers.
- Positive: cache-only status removes migration burden — `index.schema_version` mismatch or a Cairn version change simply drops the file and rebuilds (§5.3 rule 4).
- Risks / costs: indexing must run on the Rayon pool and never block rendering (REQ-CTX-008); event storms > 500/s degrade to 60 s polling with `W-IDX-STORM` (§5.3).
- Risks / costs: cold builds of 100k files must stay within P-11 (≤ 60 s, usable after 5 s) while degraded mode falls back to `glob`+`grep` (REQ-CTX-009, T-CTX-010).
