# ADR-0020: No mid-stream SSE resume

- **Decision:** REQ-PROV-009 / REQ-PROV-010 (SPEC §4.7)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Architecture

## Context

Provider streams disconnect mid-response for many reasons (network blips, idle timeouts —
`E-PROV-IDLE` after 45 s without bytes, §4.3). SSE defines a resume mechanism via the `Last-Event-ID`
header and `id:`/`retry:` fields, and the Cairn SSE parser records `id` and `retry` — but rule 2 of
§4.3 states they are "recorded but unused in v1 (no auto-reconnect replay — see §4.7)".

Whatever Cairn does with partial content affects three contracts at once: the model transcript (a
partial assistant message must never be persisted — REQ-PROV-009), the tool-argument pipeline
(replayed partial deltas could duplicate or reorder JSON tool arguments, §4.3 partial-assembly), and
the retry matrix (§4.5: `E-PROV-IDLE` is retryable, 5 attempts, "No partial content replay
(§4.7)"). The five adapters differ in streaming dialect (§4.2), so any resume scheme must work
uniformly across Anthropic, OpenAI, OpenAI-compatible proxies, Ollama and vLLM.

## Decision

**Cairn does not resume partially-received assistant content.** On disconnect after any content was
received, the whole model call is retried from the original request — idempotent because prompts
include no server-side state. REQ-PROV-009: on retry after partial content, the partial text MUST
be discarded from the model transcript; the UI MAY show it struck-through with label
`reconnecting…`, but MUST NOT persist it to the session as an assistant message. REQ-PROV-010
records the rationale (below).

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| SSE resume via `Last-Event-ID` / `id:`+`retry:` replay | Unsupported or unreliable across the five adapters; replaying partial deltas risks duplicated or reordered content in tool arguments (REQ-PROV-010). |

## Consequences

- Positive: one uniform recovery path across all five adapters, reusing the existing backoff matrix (§4.5) instead of a per-adapter resume protocol.
- Positive: the session transcript can never contain partial, duplicated or reordered assistant content — asserted by T-PROV-009 (struck-through UI text; no partial assistant message persisted) and T-FAULT-001 (disconnect mid-tool-args → retry, no partial message).
- Risks / costs: a disconnect late in a long response discards everything already received and regenerates the whole call — the cost of correctness is re-billed tokens and added latency, bounded only by the 5-attempt / 180 s per-call budget (REQ-PROV-005).
- Risks / costs: retries exhausted end provider-fatal (exit 3, §11.2) with `E-PROV-IDLE`/`E-PROV-NET` — repeated disconnects are surfaced as failure rather than silently stitched together.
