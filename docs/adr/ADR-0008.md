# ADR-0008: Session storage

- **Decision:** D-08 (SPEC §2.1)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Architecture

## Context

Sessions are the user's audit trail and the carrier of resumable state: messages, tool results,
mode/plan/todo state, usage/cost totals and checkpoint pointers (§11.7 resume semantics). They
must survive `kill -9` (risk R6, §15.5: session corruption on crash), migrate atomically with a
backup (REQ-CLI-009, T-SESS-011), preserve unknown record types verbatim (T-SESS-012), support
concurrent readers, export to md/json/html (REQ-CLI-010), and resume a 20 MB / 5,000-record session
within 400 ms (P-19). Records are written with `write`+`fsync` per record so a torn last line can
be discarded on load (REQ-LOOP-006, T-SESS-020).

## Decision

**JSONL, one file per session, append-only, with a versioned header record.** The file lives at
`<sessions>/<workspace_sha256_16>/<ulid>.jsonl`, mode `0600`; the mandatory first `header` record
carries `schema_version`, session metadata and optional `plan_id` (§11.7). Per the spec's
rationale: append-only is crash-safe (a partial last line is truncated on load), human-diffable,
trivially exported, and concurrent readers are safe.

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| SQLite | A locked DB file corrupts the "resume after kill -9" story and complicates `export`. |
| Single JSON blob | Not chosen; the spec records no separate rationale — append-only JSONL satisfies the stated positives (crash-safe, human-diffable, trivially exported, safe concurrent readers) and a monolithic blob does not give the append-only torn-line behavior. |

## Consequences

- Positive: crash safety is by construction — a torn last line is discarded on load (T-SESS-020), and tombstones give a clean delete lifecycle (§11.7 retention GC).
- Positive: sessions are human-diffable and trivially exportable (md/json/html), and readers never block the writer.
- Risks / costs: append-only files grow linearly, so retention GC (90 days / 500 sessions per workspace, §11.7) and the 50 MB load-shedding rule (§13) are required companions of this choice.
- Risks / costs: format evolution is forward-only — migrations must be atomic with a `.bak-v<n>` first (REQ-CLI-009) and unknown record types must survive rewrites (T-SESS-011, T-SESS-012).
