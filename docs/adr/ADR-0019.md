# ADR-0019: Shadow-ref checkpoint mechanism

- **Decision:** SPEC §9.8 (checkpoint mechanism)
- **Status:** Accepted (2026, Cairn 1.x)
- **Category:** Architecture

## Context

Checkpoints are Cairn's undo backbone: one before every turn, one before each `git_commit`
(label `pre-commit:<sha>`), one before plan execution (`plan:<plan_id>`), with per-tool
checkpoints off by default (`checkpoint.per_tool = false`) — §9.8 granularity. The mechanism must
satisfy hard constraints: it MUST NOT modify the user's `.git/index` or stash — `git status
--porcelain` must be byte-identical before and after 10 checkpoints (REQ-SAFE-016, T-CHK-010); it
MUST complete in ≤ 200 ms for repos with ≤ 1,000 changed files (REQ-SAFE-017, P-17, T-CHK-017);
untracked files must be included so they are restorable; and restore must be safe against ref
tampering — restore verifies the tree hash matches the ref (§9.9, T-CHK-012 → `E-CHK-HASH`).

Retention is bounded: last 50 checkpoints per session, last 200 globally,
`checkpoint.max_total_bytes = 1 GiB`, with a startup GC of unreachable Cairn-only objects (§9.8).
Outside a git repo there is no ref namespace at all, so a fallback is required (REQ-SAFE-018 caps
it: > 500 changed files in a non-git dir → copies capped at 200 MiB, else `E-CHK-DISK`).

## Decision

**Shadow-ref git approach.** Per checkpoint: Cairn builds a *temporary index file*
(`GIT_INDEX_FILE=$CAIRN_TMP/index-<id>`) seeded from `.git/index`, applies `add -A`
--intent-to-add semantics to it, writes a tree (`write-tree` semantics), then creates
`refs/cairn/checkpoints/<session_short>/<seq>` → a commit object whose parent is `HEAD` (or none)
with message `cairn checkpoint <label> turn=<n>`. The working tree is NOT modified — only a commit
object and a ref are written — and untracked files are included in the tree. Diffs against the
previous checkpoint use libgit2 `diff_tree_to_tree`. Restore uses a three-way `diff3` merge between
checkpoint tree, current worktree and HEAD in git repos; in non-git directories the fallback
creates `.cairn/checkpoints/fs/<id>/` copies of changed files only (full copies ≤ 8 MiB,
hardlinks for unchanged larger files). The default restore policy is
`RestorePolicy::CairnFilesOnly` (§9.8 commands table).

## Alternatives rejected

| Alternative | Why it was rejected |
|-------------|---------------------|
| Copying files to `.cairn/checkpoints/<id>/` | 2× disk use on large repos, misses deletions/permissions, slow (10k files ≈ 400 MB). |
| `git stash` | Mutates the user's index and stash stack; unsafe alongside the user's own stashes. |

## Consequences

- Positive: checkpoints are invisible to the user's git state (REQ-SAFE-016, T-CHK-010) and cheap — ≤ 200 ms for ≤ 1,000 changed files (REQ-SAFE-017, T-CHK-017).
- Positive: untracked files are captured (restorable), refs are local-only, and restore verifies the tree hash (§9.9, T-CHK-012) before touching anything.
- Risks / costs: outside a git repo the copy fallback is slower and capped — non-git dirs > 500 changed files can hit `E-CHK-DISK` and disable checkpointing for that turn (REQ-SAFE-018, T-CHK-015).
- Risks / costs: restore must never trample user work — `/undo` leaves files Cairn never touched alone (CairnFilesOnly, T-CHK-014), conflicts escalate to `E-CHK-MERGE` with a `Full` offer (T-CHK-016), and a session `git_commit` requires `/undo … --hard` (REQ-SAFE-015).
